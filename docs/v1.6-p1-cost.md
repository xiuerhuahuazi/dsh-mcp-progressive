# Lazy connections: process lifetime and tool-definition size

A desktop check used one stopped server with 170 cached tools, `lazyConnect` enabled for the row, and `warmIdleMs: 600000`. Search could still find its tools with the `[lazy]` marker. A single `mcp_call` started the server and reached the tool, which returned its own domain error. No tool was loaded into the conversation.

| Observation | Before call | After lazy start and call |
|---|---:|---:|
| Visible tool definitions | 55 | 55 |
| Serialized tool-definition characters | 58,357 | 58,357 |
| Visible MCP tools | 0 | 0 |
| Server child process | absent | present (417,040 KB RSS) |

Start plus dispatch took 4.388 seconds in this run. After the configured ten-minute idle interval the child process was absent again. A separate auto-prime check observed two running client rows cache their tools and stop; an already stopped row stayed stopped. Custom plugins outside `dsh-mcp-client` rows are not managed this way.

The unchanged character count applies only to the serialized tool definitions. This check did not measure provider usage, billing, long-window memory consumption or latency percentiles. See the separate [strategy measurement](../README.md#measured-usage-direct-call-load-and-keep-or-toggle) for whole-task request and token totals.
