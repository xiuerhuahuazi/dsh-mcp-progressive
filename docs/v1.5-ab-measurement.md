# Historical v1.5 measurement: tool-definition payload

Two request headers, from different dates, DSH builds and conversation histories, were compared. The script selected the header with the largest tool array in each capture and measured serialized tool definitions, **not provider input tokens or charges**.

| Header | Visible tools | MCP tools | Meta tools | Tool-definition chars |
|---|---:|---:|---:|---:|
| Before | 269 | 210 | 0 | 547,966 |
| After | 55 | 0 | 5 | 58,014 |

The before header included 501,626 characters of MCP schemas. The after header had no visible MCP schemas and 3,569 characters of meta-tool definitions. Comparing those two blocks gives a 99.3% reduction in **schema characters for this pair**, not in total usage or cost. Other tools changed independently. The headers do not establish that the same servers were connected or that a load caused a particular cache outcome.

To repeat the method, set `BEFORE` and `AFTER` to two captures of your own (`.jsonl` or `.jsonl.zstd`). No original captures are distributed.

```sh
node scripts/measure-tools-payload.mjs --self-test
node scripts/measure-tools-payload.mjs --before "$BEFORE" --after "$AFTER"
```

The script’s token estimates use 3.224 characters per token. For a separate comparison using reported cached and uncached input, see the [v1.6.0 strategy measurement](../README.md#measured-usage-direct-call-load-and-keep-or-toggle).
